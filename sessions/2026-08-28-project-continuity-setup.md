# 継続開発用ドキュメント構造の整備

## 目的

将来参加する人間や AI エージェントが、プロジェクトの現在地、実構成、判断理由、作業履歴を短時間で把握できる管理構造を用意する。

## 調査したこと

- リポジトリ全体のファイル一覧と Git の追跡対象
- 既存の `README.md` の内容
- Git 履歴と現在のブランチ状態
- リポジトリ内外の `AGENTS.md` の有無

調査時点では、初回コミットに含まれる 2 行の `README.md` 以外にプロジェクトファイルはなく、実装や技術選定は確認できなかった。

## 変更したファイル

- `README.md`
- `AGENTS.md`
- `CURRENT.md`
- `ARCHITECTURE.md`
- `decisions/README.md`
- `sessions/README.md`
- `sessions/2026-08-28-project-continuity-setup.md`

## 実装内容

- 利用者向け README に、現時点で起動対象や依存関係がないことを明記した。
- AI エージェントの調査、実装、検証、引き継ぎのルールを定義した。
- 現在地と次のアクションを `CURRENT.md` に集約した。
- 実装が存在しないという現行構成を `ARCHITECTURE.md` に記録した。
- 設計判断とセッションログの記載規約を用意した。

## 発生した問題

- 現行コードがないため、技術スタックやシステム構成をコードから特定できなかった。
- ドキュメント管理以外の実装対象と受け入れ条件は提示されていなかった。

## 解決方法

- 理想の構成を推測で追加せず、各項目が未定義または未実装であることを明記した。
- 追加の機能は勝手に仮定せず、次回の要件確認事項とした。

## 実行した検証

- リポジトリ内のファイル一覧と必須文書の存在確認
- 文書内リンクと Markdown の基本的な整合性確認
- `git diff --check` による空白エラーの確認

実行可能なコードとツールチェーンがないため、lint / typecheck / test / build は対象外とした。

## 残っている問題

- プロダクト要件と受け入れ条件が未定義である。
- 技術スタック、実装、自動検証、デプロイ構成がない。

## 次回への引き継ぎ

`AGENTS.md` と `CURRENT.md` から読み始め、実装前にプロダクト要件を確認する。技術選定を行う際は比較した選択肢とトレードオフを最初の設計判断ログに残す。
