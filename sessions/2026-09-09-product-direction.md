# タイル型マルチ AI ブラウザ方針の決定

## 目的

曖昧だった「複数 AI を扱う基盤」の利用イメージを、実装可能なプロダクト方針と最小版の範囲に落とし込む。

## 調査したこと

- 現在の文書、Git 履歴、過去の作業セッション
- 外部 Web ページの埋め込み制約
- Electron `WebContentsView` と永続セッション
- Chrome 拡張によるタブ、ウィンドウ、サイドパネル操作の範囲

## 変更したファイル

- `README.md`
- `CURRENT.md`
- `ARCHITECTURE.md`
- `decisions/001-tiled-electron-browser.md`
- `sessions/2026-09-09-product-direction.md`

## 実装内容

- 複数の AI サービスの既存 Web 画面を一つのウィンドウに分割表示する方針を定義した。
- Electron、TypeScript、React、`WebContentsView` を初期技術方針とした。
- 2 分割・4 分割、基本ナビゲーション、セッション保持、ワークスペース保存を最小版候補とした。
- API 統合と DOM 依存の自動操作を初期版の対象外とした。
- セキュリティ境界と技術上のリスクを記録した。

## 発生した問題

- 対象 AI サービスごとの Electron 上でのログイン可否は、実装前には確定できない。
- 複数画面の実用的な上限は、実測しなければ判断できない。

## 解決方法

- サービス固有の対応を先に仮定せず、最小構成を作った後の互換性検証項目とした。
- 初期版を直接操作型に限定し、自動操作に伴う不安定性と利用条件上のリスクを切り離した。

## 実行した検証

- 文書間でプロダクト目的、技術方針、次の作業が矛盾していないことを確認した。
- `git diff --check` を実行した。

コードとツールチェーンはまだ存在しないため、lint / typecheck / test / build は対象外である。

## 残っている問題

- 実装と自動検証がまだない。
- 対象サービスと優先順位を実機で検証する必要がある。
- パッケージ管理、配布方法、対応 OS の正式決定が必要である。

## 次回への引き継ぎ

Electron、TypeScript、React の最小構成を作り、まず任意の 2 ページを `WebContentsView` で左右に表示する。外部ページには Node.js 権限を与えず、ログイン、ポップアップ、新規ウィンドウの挙動を早い段階で検証する。
